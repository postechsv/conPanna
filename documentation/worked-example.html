Fruits in Baskets: One Certificate from Root to Leaves

The paper presents the calculus one rule at a time. This page follows a single complete certificate: the whole proof tree first, then one instance of each rule, chosen to show the most.

1The problem

inductive Fruit  | a | b | c
abbrev    Fruits  := ACU Fruit       -- finite multisets of Fruit
inductive Basket | f (x : Fruits)    -- f: a free constructor
abbrev    Baskets := ACU Basket      -- finite multisets of Basket

$\mathsf{ACU}\ S$ has $\varnothing$, singletons $\{s\}$ and union $\cup$ (associative, commutative, unit $\varnothing$). Variables: $X, Y, W : \mathsf{Fruits}$ and $R, S, T : \mathsf{Baskets}$.

$$R\cup\{\underbrace{f(\{a\}\cup X)}_{A}\}\cup\{\underbrace{f(Y)}_{B}\} \;\stackrel{?}{=}\; S\cup T\cup\{\underbrace{f(\{a\}\cup W)}_{C}\}$$

A solution, used again in §5:

$$\gamma = [X{\mapsto}\varnothing,\ Y{\mapsto}\{b\},\ W{\mapsto}\{b\},\ R{\mapsto}\{f(\{a,b\})\},\ S{\mapsto}\{f(\{a\})\},\ T{\mapsto}\{f(\{b\})\}]$$

Both sides are $\{f(\{a\}),\ f(\{b\}),\ f(\{a,b\})\}$. Maude returns 112 answers; the certificate uses 8 of them, one per Cover leaf.

Claim (the root): $\langle \mathrm{id};\ E;\ \varnothing\rangle \Vdash \Sigma$, where $E$ is the equation above: every solution is an instance of some answer in $\Sigma$.

3The ideas the tree uses

State
$\langle\alpha;E;D\rangle$: $\alpha$ maps the original variables to terms over the current variables, $E$ lists the pending equations and $D$ the recorded disequations. Its solutions are the values of the current variables that satisfy $E$ and $D$; each one gives the solution $\alpha$ of the original problem.
Judgment
$\langle\alpha;E;D\rangle\Vdash\Sigma$: every solution of the state is covered by some answer in $\Sigma$.
Alien
An element of a multiset that is not a variable: the fruit $a$ inside a basket, or a whole basket such as $A$ among the baskets. Solve treats aliens as opaque elements and counts their copies.
Count equation
For a multiset equation and one element $e$, the copies of $e$ on each side must agree. With $r, s, t$ the copies of $e$ in $R, S, T$, the problem gives $r + [e{=}A] + [e{=}B] = s + t + [e{=}C]$, where $[e{=}A]$ is $1$ if $e$ is $A$, else $0$.
Data $P$, $\mathcal B$
For each alien $c$, the least solutions $P_c$ of its count equation; and the basis $\mathcal B$, the least nonzero solutions where no alien occurs. Every solution is one particular solution plus a sum of basis vectors.
Choice, $\theta_\pi$
A choice $\pi$ picks one particular solution per alien. It determines the substitution $\theta_\pi$: each multiset variable gets $\pi$'s copies of the aliens plus one fresh variable $Z_j$ per basis vector. Solve has one premise per choice.
Compatible, clique
Two aliens on the same side are compatible when nothing rules out that they are equal. A clique is a set of pairwise compatible aliens; they may all denote one element, so their count equations are added together, and (S2) is checked for that sum.
(S1)–(S3)
(S1) the data solve the count equations; (S2) every solution, for every clique, lies above some sum of picks; (S3) every nonzero solution without aliens lies above some basis vector. Together they say no solution is lost.
Cover
Closes a state with no pending equations: one answer $\sigma$ and a witness $\beta$ with $\alpha = \beta\circ\sigma$ modulo ACU.
Not in this tree Delete drops a trivial equation $t \stackrel{?}{=} t$. Clash closes a state whose constraints contradict each other, for example $0 \stackrel{?}{=} \mathsf{s}(N)$ for numbers, or a disequation $t \ne t$. A Solve can also have no premise at all, when some alien has no particular solution: $\{f(X)\} \stackrel{?}{=} \{f(Y)\}$ with $f(X)\ne f(Y)$ recorded in $D$ gives $1 = 0$ at $e = f(X)$, so $P_{f(X)} = \varnothing$, there is no choice, and the branch is closed.

4One instance of each rule

Each instance is shown as its rule: premises above the line, the node's state below. Labels used throughout:

$$A = f(\{a\}\cup X),\quad B = f(Y),\quad C = f(\{a\}\cup W),\qquad E = \bigl(R\cup\{A\}\cup\{B\} \stackrel{?}{=} S\cup T\cup\{C\}\bigr).$$

For a multiset equation, $r, s, t$ are the copies of an element $e$ in $R, S, T$, and $[e{=}A]$ is $1$ if $e = A$, else $0$.

4.1Identify: $J_1$

$$\frac{\overbrace{\langle\mathrm{id};\ B\stackrel{?}{=}C,\ E;\ \varnothing\rangle}^{J_2}\qquad\overbrace{\langle\mathrm{id};\ E;\ B\ne C\rangle}^{J_7}}{\underbrace{\langle\mathrm{id};\ E;\ \varnothing\rangle}_{J_1}}\ \textsf{Identify}$$

where $E = \bigl(R\cup\{A\}\cup\{B\} \stackrel{?}{=} S\cup T\cup\{C\}\bigr)$, $\ B = f(Y)$, $\ C = f(\{a\}\cup W)$.

$B$ (left) and $C$ (right) are equal exactly when $Y = \{a\}\cup W$. If equal, they cancel; if not, $C$ must be matched by something else. The count depends on which, so split. $J_7$ splits $A\sim C$ the same way. ($A$ and $B$ are on the same side: no split, they form a clique in §4.3.)

4.2Decomp and Elim: $J_2$, $J_3$

$$\frac{\overbrace{\langle\mathrm{id};\ Y\stackrel{?}{=}\{a\}\cup W,\ E;\ \varnothing\rangle}^{J_3}}{\underbrace{\langle\mathrm{id};\ f(Y)\stackrel{?}{=}f(\{a\}\cup W),\ E;\ \varnothing\rangle}_{J_2}}\ \textsf{Decomp}\qquad f\text{ is injective.}$$

where $E$ is carried along unchanged.

$$\frac{\overbrace{\langle[Y{\mapsto}\{a\}\cup W];\ R\cup\{A\}\cup\{C\}\stackrel{?}{=}S\cup T\cup\{C\};\ \varnothing\rangle}^{J_4}}{\underbrace{\langle\mathrm{id};\ Y\stackrel{?}{=}\{a\}\cup W,\ E;\ \varnothing\rangle}_{J_3}}\ \textsf{Elim}\qquad B[Y{:=}\{a\}\cup W] = C.$$

where $E = \bigl(R\cup\{A\}\cup\{B\} \stackrel{?}{=} S\cup T\cup\{C\}\bigr)$ with $B = f(Y)$; substituting $Y := \{a\}\cup W$ turns $B$ into $C = f(\{a\}\cup W)$.

5Why the whole tree proves completeness

Every rule has the same shape of argument: each solution of the conclusion is a solution of some premise, with the same solution of the original problem. So a solution of the root travels down the tree, one rule at a time, until it reaches a leaf. Every leaf is covered by an answer. Hence every solution of the root is covered.

The path of $\gamma$ from §1 ($X=\varnothing$, $Y=W=\{b\}$, $R=\{f(\{a,b\})\}$, $S=\{f(\{a\})\}$, $T=\{f(\{b\})\}$):

AtWhat $\gamma$ does
J1$B = f(\{b\}) \ne f(\{a,b\}) = C$: to $J_7$.
J7$A = f(\{a\}) \ne C$: to $J_{13}$.
J13At $e = A$: $(r,s,t) = (0,1,0)$, $A$ in $S$. At $e = B$: $(0,0,1)$, $B$ in $T$. At $e = C$: $(1,0,0)$, $C$ in $R$. Nothing else: $Z_1 = Z_2 = \varnothing$. Choice $\pi_2$.
J15Covered by $\sigma_{31}$ with $U_1 = U_3 = \{b\}$, $U_2 = U_4 = U_5 = \varnothing$.

The tree does not need to say in advance which path a solution takes. Each rule only guarantees that some child receives it, and the leaves account for all children.

6Proof construction

The tree is built by the Maude producer, not by Lean, and it is built without search. The producer follows a fixed strategy: it always works on the first pending equation; an equation between constructor terms gets the one rule its shape allows (Delete, Elim, Decomp or Clash); a multiset equation gets Solve, unless (S2) fails for some clique, and then Identify splits the first failing pair. The hard parts come from Maude's own algorithms: each Solve's data $P$, $\mathcal B$ and its compatible pairs from unification (metaUnify), and each leaf's answer and witness from matching (metaMatch, taking the first answer that matches).

Why no backtracking is needed. Every rule keeps all solutions: each solution of a node reaches one of its children (§5). So no step can lead into a dead end that another order would have avoided, and nothing ever has to be undone. The construction can only stop at a leaf that no single answer covers; the producer then reports it as stuck, as for a deliberately incomplete answer set.

7The same tree in Lean

The certificate is checked in Lean as producer/tests/pipeline/t7_example.lean. Each node is one step of the proof script:

NodesLean step
J1, J7refine identify a b ?_ ?_
J2, J8refine decomp [new equations] (by acu_decomp …), proved by the constructor's injectivity
J3refine elim f (by acu_elim …)
J4, J9, J10, J13refine solve with the multiset variables, the aliens, the coefficients and compatible pairs, the data $P$ and $\mathcal B$, and (S0)–(S3); then acu_branches opens one goal per choice
leavescover with the answer and the witness

Two kinds of bookkeeping step have no node in the tree: checkpoint, which restates each state in direct form, and rename, which names Solve's fresh variables.
